- (constraint) Brownfield implementation reality: FastAPI serves HTML and API; htmx performs row-level fragment swaps; bench/tools owns domain mutations; SQLite is the Bench catalog and state store.
- (constraint) Product boundary: the local UI is a trusted localhost operator surface; no hosted authentication, authorization, employee filtering, real IAM provisioning, AWS deployment, or multi-tenant backoffice is in this slice.
- (decision) [ADOPTED] Keep the hybrid engine boundary: Strands/agentic routing for conversational work, LangGraph for the fixed AM/PM cycle, deterministic tools for catalog/state/report mutations.
- (decision) [ADOPTED] Keep relational SQLite as the Bench source of truth for catalog, assignments, task instances, check-ins, notification records, simulated access context, and the new audit records; do not reintroduce YAML for Bench.
- (decision) [ADOPTED] Keep plans and reports as read-only projections generated from verified database state; rendered Markdown cannot mutate task, permission, approval, or audit state.
- (decision) [ADOPTED] Keep the thin-channel rule: web UI, JSON API, Teams adapter, CLI, and scheduled graph call the same bench/tools seams; channels do not own business rules or persistence.
- (decision) UI mutation contract: full-page creates/person mutations use 303 redirect; inline catalog row mutations return one targeted HTML fragment with stable ids and no unrelated page replacement; server confirmation is the source of truth.
- (decision) People lifecycle contract: person records gain an explicit local lifecycle/archive state separate from computed bench-date status; archive hides a person from active views while preserving task history, reports, notifications, and audit history.
- (decision) Audit contract: every state-changing UI/API/tool operation records local actor identity, timestamp, entity, action, outcome, and enough target context to explain the change; audit write occurs in the same SQLite transaction as the mutation when possible.
- (decision) Local actor contract: until hosted identity exists, the operator actor is explicit and consistently supplied by a local configuration/request context; the system must not silently emit anonymous audit records. Exact UX/config source remains an open decision.
- (decision) Access/approval contract: role/profile permissions and approval-required actions remain source data; UI may show expected/requested/pending simulated state and audit it, but no local action can claim granted access or provision it.
- (decision) Notification/report contract: a saved report, queued notification, and delivered notification are distinct states and projections; UI must show recipient, durable local report path/status, queue status, and delivery timestamp/status independently.
- (decision) Catalog safety contract: role and track deletion is refused while assigned; task deletion cannot erase person history and therefore requires preserving or detaching existing person-task instances; knowledge and responsible changes are audited; responsible update is first-class, not delete-and-recreate-only.
- (decision) Navigation contract: every operator surface is reachable from persistent navigation or a documented parent action; Tracks is top-level discoverable, while tasks and responsibles are owned by Track detail.
- (decision) Accessibility/responsive contract: native HTML semantics, labelled forms/dialogs, keyboard-complete flows, text-plus-color status, focus-preserving htmx feedback, 200% readability, and horizontal scrolling for dense tables below desktop widths are acceptance invariants.
- (decision) Future storage compatibility contract: tools expose storage-agnostic domain operations and stable identifiers; SQLite-specific schema/query code stays behind db/tools, so a later DynamoDB adapter can replace persistence without changing UI/API/Teams contracts.
- (assumption) The local audit log can initially be an append-only SQLite table and does not require external observability for this UI completion slice.
- (question) Decide the exact local actor identity source and editability: environment/config default, explicit UI session field, or both; define the value shown when no actor is configured.
- (question) Decide whether person deletion is never allowed and archive is the only lifecycle removal, or whether a hard-delete path is required for test/demo cleanup.
- (question) Decide the simulated approval vocabulary and state transitions that the UI may display (for example expected, pending, approved-simulated, denied-simulated) without implying provisioning.
- (question) Decide whether responsible identity is unique per track/email and whether a responsible may be shared across tracks, before enforcing update/delete constraints.
- (direction) Before stories: add schema/tool seams for people archive/edit, responsibles update, audit/action history, notification/report status queries, and explicit approval projection; then make web routes thin callers of those seams.
- (direction) Amend ADR 0003 with task-history preservation and audit/lifecycle implications; amend ADR 0004 with UI/API actor propagation and status projection; replace or clarify duplicate ADR 0001/0004 references and add the UI spine as the governing feature artifact.
- (direction) Amend docs/ARCHITECTURE.md to distinguish the Bench local architecture from the older YAML onboarding sketch and to name the local operator trust boundary plus future API/DynamoDB seam.
