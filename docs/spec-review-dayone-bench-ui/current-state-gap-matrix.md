# Current-state gap matrix

| Area | Evidence in current state | Required contract change | Acceptance evidence |
|---|---|---|---|
| Audit | `db.py` has no audit table; tools/routes do not propagate `BENCH_ACTOR`. | Add shared actor context and append audit records for every listed mutation, with outcome and target context. | Mutation tests assert actor, entity, action, outcome, timestamp, and detail; person detail exposes history. |
| Person lifecycle | People have computed date status but no explicit archive lifecycle; no edit/archive/restore/archived views. | Separate lifecycle/archive from computed `inactive`, `pre_bench`, `active`; archive-only UI removal; preserve all history. | Create, edit, archive, list active/archived, restore, and date-change tests. |
| Task deletion | `catalog.delete_task` deletes `person_tasks`; `start_bench` resets task/check-in history. | Physical delete only pre-instantiation; otherwise archive/inactivate and retain historical identity; do not silently reset instantiated history. | Instantiate, mutate, archive task, and verify person history remains attributable. |
| Responsibles | Add/remove exists; edit and uniqueness are absent. | Add update operation and case-insensitive `(track_id,email)` constraint; permit cross-track reuse. | Duplicate-case rejection, cross-track success, edit projection, report recipient test. |
| Reports | Reports are local files from `save_eod_report`; no durable report index/status projection. | Persist report identity/person/date/path/save status and show it outside read-only Markdown. | Generate twice/idempotence/status/path/history tests. |
| Notifications | `notifications` has created/delivered timestamps but UI does not independently project queued/delivered state. | Query explicit pending/queued/delivered/error status and recipient; preserve notification records. | Queue and delivery projection tests with timestamp/error distinctions. |
| Approval | Profile approvals exist, but UI lacks the agreed explicit projection vocabulary. | Project only `not_required`, `approval_required`, `pending_simulated`; never claim granted. | UI/API assertions reject granted copy and show each allowed state. |
| Navigation | `/tracks` exists, but current test explicitly expects no persistent Tracks link. | Add active, persistent Tracks navigation; Track detail owns Tasks/Responsibles. | Navigation tests for every destination and active state. |
| Accessibility | Existing HTML/htmx is only partial; dialog semantics, dynamic feedback, active nav, mobile/table behavior need explicit criteria. | Implement semantic labels/dialog naming/focus, associated validation, announcements, keyboard paths, status text, zoom and responsive rules. | Automated markup checks plus keyboard/screen-reader-oriented manual acceptance at 200% and narrow widths. |
| Tests/environment | Existing tests cover shipped flows, not the new lifecycle/audit/responsible/status/accessibility seams; `pytest` is unavailable in this worktree. | Require an executable `pytest` development environment before implementation validation, then add focused unit/API/UI/E2E/regression coverage. | Environment check passes and the acceptance run is recorded from an actual `pytest` execution. |
| Identity | `people.email` is currently the primary identity and is referenced by history tables. | Introduce stable `person_id`; permit safe email edits without changing historical identity. | Email-edit migration preserves every task, check-in, report, notification, conversation, and audit reference. |
| Migration/history policy | Existing schema uses ad-hoc idempotent column additions; no conflict/backfill policy exists. | Use versioned migrations, explicit backfills, fail-closed conflicts, and no automatic local history deletion. | Upgrade tests cover old DBs, duplicate responsible emails, person identity backfill, and atomic failure. |
